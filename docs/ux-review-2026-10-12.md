# Finflo usability release — October 12, 2026

The public-site review found that oversized introductions delayed access to tools, small supporting text weakened readability, and long schedules made returning to inputs or explanations cumbersome. This release prioritizes search, calculator inputs and results while retaining the existing green identity.

## Changes

- Replaced charcoal headers and introductions with forest green, mint accents and a white search field. Calculator and information pages use a compact, light introduction. Category icons distinguish finance, health, math and everyday tools with text labels alongside color.
- Removed forced mobile hero heights and shortened the directory introduction. Reduced repetitive homepage copy, clarified the selected category filter, and shortened the search placeholder so it fits phones.
- Added persistent calculator links to inputs, results and explanations. Native anchors move keyboard focus to the relevant section; scroll offsets keep headings clear of the bar. The full payment schedules remain expanded. The directory category bar also stays available while scrolling.
- Increased form labels, result explanations, card descriptions and export actions. Search clear buttons, modal close buttons, quick links and export actions have larger touch targets. Input borders have stronger contrast. Calculate/reset controls wrap on narrow translated layouts.
- Preserved immediate desktop CSV/PDF downloads and mobile save/share fallbacks. Updated the homepage explanation to name the actual export and copy-link actions.
- Added three translated navigation labels in all seven secondary languages and verified Arabic, German and Hindi layouts at 320px.

## Validation

The [check record](validation/ux-2026-10-12/checks.json) records 3,030 passing unit cases, production build and type/lint checks, 9,690 translation messages per secondary language, and 94 distinct desktop-browser cases plus 16 Android/iPhone export cases across the initial, continuation and targeted recheck runs. The [crawl](validation/ux-2026-10-12-seo.json) checked all 1,944 sitemap pages and 1,952 internal paths without errors or duplicate titles/descriptions.

New browser tests exercise returning from a 360-row table, keyboard focus after section navigation, stale results, recalculation, printing, directory navigation and narrow translated layouts. Existing checks cover accessibility, mobile overflow, search, preferences and downloads. Automated accessibility checks are not a complete accessibility certification.

Two older browser assertions expected extra decimal places even though the existing output policy is two decimals. They now expect the displayed/exported values; calculation code was unchanged. Concurrent test runners initially collided in their artifact directory. The affected cases passed with separate output directories; the evidence logs retain those failures and rechecks.

The [performance report](validation/ux-2026-10-12/performance.json) uses the existing cold-cache, throttled desktop/mobile lab procedure. It does not establish field Core Web Vitals, conversion improvements or increased attention. Those require real usage data. Analytics remains inactive.

## Release and rollback

Deployment uses the existing GitHub `main` → Railway workflow. Local validation is separate from live deployment verification. The release can be rolled back by reverting its commit. No URL, DNS, hosting-provider or calculator-method migration is involved.
